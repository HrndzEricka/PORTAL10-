1. Computación en la nube: conceptos

Cloud computing (computación en la nube)

Es un modelo que permite acceder a través de Internet y bajo demanda a recursos informáticos (servidores, almacenamiento, bases de datos, redes, software) que están en centros de datos de un proveedor. El usuario no compra ni mantiene el equipo físico: usa el recurso y paga según lo que consume.

Idea clave: "la nube" no es algo abstracto; son computadoras reales ubicadas en centros de datos de otra empresa, a las que accedemos por la red.
Guardar fotos en Google Drive, ver una serie en Netflix o usar Microsoft 365 desde el navegador.

Modelos de negocio en la nube

Son las formas en que los proveedores cobran y ofrecen sus servicios:

ModeloDescripciónEjemplo
Pago por uso (pay-as-you-go)Se paga solo por lo que se consume (horas, GB, peticiones).Una máquina virtual en AWS cobrada por hora.
SuscripciónPago fijo mensual o anual por un servicio.Microsoft 365, Spotify, Canva Pro.
FreemiumVersión básica gratis y funciones avanzadas pagadas.Dropbox (2 GB gratis), Google Drive (15 GB gratis).
Instancias reservadasSe compromete un uso de 1 a 3 años a cambio de descuento.Servidores reservados en Azure.
PublicidadEl servicio es gratuito y se financia con anuncios.Gmail gratuito.

Máquina virtual (VM)

Es una computadora simulada por software que funciona dentro de una computadora física (anfitrión o host). Tiene su propio sistema operativo (invitado o guest), CPU virtual, memoria, disco y red. Un programa llamado hipervisor reparte los recursos físicos entre varias VM.

En una computadora con Windows se instala VirtualBox y dentro se crea una VM con Linux Ubuntu.

Contenedor y API

Contenedor: paquete ligero que incluye una aplicación y todo lo que necesita (librerías, configuración) para ejecutarse. A diferencia de la VM, no lleva un sistema operativo completo: comparte el núcleo (kernel) del sistema anfitrión, por eso arranca en segundos y ocupa menos. Herramientas: Docker, Kubernetes (orquestador de contenedores).

API (Interfaz de Programación de Aplicaciones): conjunto de reglas que permite que dos programas se comuniquen. En la nube, casi todo se controla mediante APIs: crear una VM, subir un archivo o consultar una base de datos.

2. Roles del modelo de relación en la nube

Cliente final o consumidor

Persona u organización que usa los servicios de la nube. Elige el servicio, lo configura según sus necesidades, paga por él y es responsable de sus datos, usuarios y contraseñas.

Ej.: un colegio que usa Google Workspace para sus estudiantes.

Proveedor o prestador

Empresa que ofrece los recursos: construye y mantiene los centros de datos, el hardware, la red, la virtualización y garantiza la disponibilidad según un acuerdo de nivel de servicio (SLA).

Ej.: Amazon Web Services, Microsoft Azure, Google Cloud.

Modelo de responsabilidad compartida: el proveedor protege la nube (infraestructura física, red, hipervisor); el cliente protege lo que pone en la nube (datos, cuentas, configuraciones, accesos).

Otros roles reconocidos (NIST): intermediario o bróker (gestiona servicios entre cliente y proveedores), auditor (evalúa seguridad y cumplimiento) y portador o carrier (proveedor de conectividad).

3. Virtualización

Concepto

La virtualización es la tecnología que permite crear versiones virtuales (simuladas por software) de recursos físicos, como servidores, almacenamiento, redes o sistemas operativos. Así, un solo equipo físico puede ejecutar varios sistemas independientes al mismo tiempo. El software que lo hace posible es el hipervisor.

  • Hipervisor tipo 1 (bare metal / nativo): se instala directamente sobre el hardware. Ej.: VMware ESXi, Microsoft Hyper-V Server, Xen.
  • Hipervisor tipo 2 (alojado / hosted): se instala como un programa sobre un sistema operativo. Ej.: VirtualBox, VMware Workstation, Virtual PC.

Conceptos relacionados

TérminoSignificado
Computación en la nubeServicios informáticos ofrecidos por Internet bajo demanda. La virtualización es la base tecnológica que la hace posible.
ClústerGrupo de computadoras (nodos) conectadas que trabajan juntas como si fueran una sola, para dar más potencia o alta disponibilidad (si un nodo falla, otro continúa).
CPDCentro de Procesamiento de Datos: instalación física donde se concentran servidores, almacenamiento y equipos de red de una organización, con energía de respaldo, climatización y seguridad física.
Data CenterTérmino en inglés equivalente a CPD. Los proveedores de nube tienen enormes data centers distribuidos en regiones del mundo.
CRMCustomer Relationship Management: software para gestionar la relación con clientes (ventas, contactos, seguimiento). Hoy suele ofrecerse desde la nube como SaaS. Ej.: Salesforce, HubSpot.
Otros: host / guestHost = equipo físico anfitrión; guest = sistema virtual invitado.
Otros: snapshot"Fotografía" del estado de una VM que permite volver atrás si algo falla.
Otros: ERPEnterprise Resource Planning: software que integra finanzas, inventario, recursos humanos, etc. (Ej.: SAP).

Historia de la virtualización

AñoHecho
1960sIBM desarrolla el sistema CP-40 / CP-67 para mainframes, que permitía dividir un gran computador entre varios usuarios (tiempo compartido).
1972IBM lanza VM/370, primer sistema comercial de máquinas virtuales.
1998–1999Se funda VMware y lanza VMware Workstation para computadoras x86.
2003Aparece Xen (Universidad de Cambridge), hipervisor de código abierto. Microsoft adquiere Virtual PC.
2005–2006Intel (VT-x) y AMD (AMD-V) agregan soporte de virtualización en los procesadores.
2007Se libera VirtualBox (Innotek, luego Sun y Oracle).
2008Microsoft lanza Hyper-V con Windows Server 2008.
2013Surge Docker y se populariza la virtualización con contenedores.

Ventajas de la virtualización

  • Ahorro de costos: menos servidores físicos, menos energía y espacio.
  • Mejor aprovechamiento del hardware (un servidor pasa de usar 15 % a 70–80 % de su capacidad).
  • Aislamiento: si una VM falla o se infecta, no afecta a las demás.
  • Rapidez: crear un servidor nuevo toma minutos, no semanas.
  • Respaldo y recuperación: snapshots y copias de VM completas.
  • Pruebas seguras: laboratorios para probar software o malware sin riesgo.
  • Migración: mover una VM de un servidor físico a otro sin apagarla.

Tipos de virtualización

TipoQué virtualizaEjemplo

De escritorio (VDI)El escritorio del usuario corre en un servidor y se accede remotamente.Windows 365, Citrix.
De sistema operativoVarios entornos aislados sobre un mismo kernel.Contenedores Docker.
De aplicacionesLa aplicación se ejecuta aislada sin instalarse en el equipo.App-V, aplicaciones web.

De redCrea redes lógicas independientes del cableado físico.VLAN, SDN, VPN.

Rol de la virtualización en la nube

La virtualización es el cimiento de la computación en la nube. Gracias a ella el proveedor puede:

  • Dividir sus data centers en miles de recursos virtuales y compartirlos entre muchos clientes (multi-inquilino o multi-tenant) de forma aislada.
  • Entregar recursos bajo demanda y en minutos (autoservicio).
  • Aumentar o reducir recursos automáticamente (elasticidad).
  • Medir el consumo de cada cliente para cobrarle.

5. Computación en la nube: características, historia y usos

Características esenciales (NIST)

  1. Autoservicio bajo demanda: el cliente obtiene recursos sin hablar con nadie del proveedor.
  2. Amplio acceso a la red: se accede desde cualquier dispositivo con Internet.
  3. Agrupación de recursos (pooling): los recursos se comparten entre muchos clientes.
  4. Elasticidad rápida: crece o se reduce según la demanda.
  5. Servicio medido: se mide y se cobra el consumo real.

Historia

AñoHecho
1961John McCarthy propone que la computación podría venderse como un servicio público, igual que la electricidad.
1969Nace ARPANET, antecesora de Internet. J.C.R. Licklider imagina una "red intergaláctica" de computadoras.
1999Salesforce ofrece software empresarial a través de un sitio web (inicio del SaaS).
2006Amazon lanza AWS con S3 (almacenamiento) y EC2 (servidores virtuales). Google populariza el término cloud computing.
2008Google App Engine (PaaS).
2010Microsoft Azure disponible comercialmente. Nace OpenStack (nube de código abierto).
2011El NIST publica la definición oficial de computación en la nube (SP 800-145).
2014 en adelanteComputación sin servidor (serverless, AWS Lambda), contenedores, multicloud y servicios de inteligencia artificial en la nube.

Tipos de soluciones (modelos de servicio)

IaaS

Infraestructura como servicio: se alquilan servidores virtuales, redes y almacenamiento.
Ej.: AWS EC2, Azure VM.

PaaS

Plataforma como servicio: entorno listo para desarrollar y publicar aplicaciones.
Ej.: Google App Engine, Heroku.

SaaS

Software como servicio: aplicación lista para usar desde el navegador.
Ej.: Gmail, Microsoft 365, Canva.

Otros (XaaS)

FaaS (funciones/serverless), DaaS (escritorio), BaaS (respaldo), STaaS (almacenamiento), SECaaS (seguridad).

Ventajas

  • No hay que invertir en equipos: se pasa de gasto de capital (CAPEX) a gasto operativo (OPEX).
  • Acceso desde cualquier lugar y dispositivo.
  • Escalabilidad y elasticidad inmediatas.
  • Actualizaciones y mantenimiento a cargo del proveedor.
  • Alta disponibilidad y respaldos en varias regiones.
  • Colaboración en tiempo real.

Seguridad en la nube (introducción)

La seguridad se basa en la tríada CID: Confidencialidad, Integridad y Disponibilidad. Medidas básicas: autenticación multifactor (MFA), cifrado de datos, control de accesos por roles, copias de seguridad, monitoreo y cumplimiento de normas (ISO 27001, ISO 27017, ley de protección de datos). 6. Componentes computacionales en la nube

Los componentes básicos son: cómputo (servidores/VM/contenedores), almacenamiento, redes, bases de datos, virtualización (hipervisor), plataforma de gestión (consola, APIs) y servicios de seguridad. El usuario accede mediante un front-end (navegador, app) y el proveedor opera el back-end (data centers).

Características de los servicios en la nube

  • Bajo demanda y autoservicio.
  • Multi-inquilino (varios clientes comparten la infraestructura de forma aislada).
  • Escalables y elásticos.
  • Medibles (pago por uso).
  • Resilientes (redundancia, alta disponibilidad).
  • Regidos por un SLA (acuerdo de nivel de servicio, ej. 99,9 % de disponibilidad).

Ventajas

  • Reducción de costos iniciales.
  • Rapidez de implementación.
  • Escalabilidad.
  • Movilidad y trabajo remoto.
  • Seguridad física profesional del proveedor.
  • Continuidad del negocio.

Desventajas o inconvenientes

  • Dependencia de la conexión a Internet.
  • Dependencia del proveedor (vendor lock-in).
  • Menor control sobre la infraestructura.
  • Riesgos de privacidad y ubicación de los datos.
  • Costos que crecen si no se controla el consumo.
  • Caídas del proveedor afectan a todos sus clientes.

Opciones de contratación

OpciónDescripción
Bajo demandaSin compromiso; se paga por hora/segundo de uso. Más caro, más flexible.
Reservada / compromisoContrato de 1 a 3 años con descuentos de hasta 70 %.
Instancias spot / interrumpiblesCapacidad sobrante muy barata, pero el proveedor puede retirarla.
Suscripción por usuarioTípico de SaaS: costo mensual por cada usuario.
Nivel gratuito (free tier)Uso limitado sin costo, útil para aprender.
Contrato empresarial / marketplaceAcuerdos personalizados o compra por medio de un intermediario (cloud broker).

Modelos de despliegue en la nube

ModeloDescripciónVentajasDesventajasEjemplo
Nube públicaLa infraestructura es del proveedor y se comparte con muchos clientes por Internet.Bajo costo, gran escalabilidad, sin mantenimiento.Menor control, datos en infraestructura compartida.AWS, Azure, Google Cloud, Gmail.
Nube privadaInfraestructura dedicada a una sola organización (en su CPD o alojada por un tercero).Mayor control, seguridad y personalización.Costo alto, requiere personal especializado.Bancos, gobierno, hospitales con VMware u OpenStack.
Nube híbridaCombina nube privada y pública conectadas, moviendo datos y aplicaciones entre ambas.Flexibilidad: datos sensibles en privada, picos de demanda en pública.Mayor complejidad de gestión y de seguridad.Un banco guarda clientes en su nube privada y usa la pública para su app móvil.

Otros modelos: nube comunitaria (compartida por organizaciones con intereses comunes, ej. universidades) y multicloud (uso de varios proveedores públicos).

1. Seguridad de datos en la nube: conceptos

La seguridad de datos en la nube es el conjunto de políticas, tecnologías y controles que protegen la información almacenada, procesada o transmitida en servicios de nube contra accesos no autorizados, pérdida o alteración. Para entenderla hay que conocer cómo se organiza y administra la nube:

ConceptoDefiniciónRelación con la seguridad
RendimientoCapacidad del servicio de responder rápido (latencia, velocidad de procesamiento, ancho de banda).Un ataque de denegación de servicio (DDoS) degrada el rendimiento; los controles de seguridad no deben volver lento el sistema.
CompetitividadVentaja que obtiene una organización al usar la nube: reduce costos, innova más rápido y llega a más clientes.Un proveedor seguro y confiable genera confianza en los clientes; una fuga de datos daña la reputación.
EscalabilidadCapacidad de aumentar o disminuir recursos según la demanda. Vertical: más potencia a un servidor. Horizontal: más servidores.Los controles de seguridad deben escalar junto con los recursos (nuevas VM nacen ya protegidas).
AbstracciónOcultar la complejidad del hardware físico y presentar al usuario recursos lógicos simples (una "VM", un "bucket").El cliente no ve el hardware, por eso depende de los controles del proveedor y del SLA.
AutomatizaciónEjecutar tareas sin intervención humana: crear servidores, aplicar parches, respaldos. Incluye Infraestructura como Código (Terraform, scripts).Reduce errores humanos de configuración, una de las causas principales de incidentes.
Motor de control para la gestión de datosPlataforma central (plano de control / orquestador) que administra dónde se guardan los datos, quién accede, las réplicas y las políticas.Aplica políticas de acceso, retención y cifrado de forma uniforme. Ej.: vCenter, OpenStack, consola de AWS.
Control de consumoMonitoreo y límites del uso de recursos (CPU, almacenamiento, tráfico) y su costo.Un consumo anormal puede indicar un ataque (ej. criptominería en una cuenta robada). Se usan alertas y presupuestos.
Control de rendimientoSupervisión de métricas (tiempo de respuesta, disponibilidad) para cumplir el SLA.Detecta caídas o saturación; herramientas: CloudWatch, Azure Monitor.
HDDC — Hardware-Defined Data CenterCentro de datos tradicional donde cada función depende de equipos físicos específicos (switch, firewall, cabina de discos). Cambiar algo implica mover hardware.Menos flexible; la seguridad depende de dispositivos físicos configurados a mano.
SDDC — Software-Defined Data CenterCentro de datos donde cómputo, almacenamiento, red y seguridad están virtualizados y controlados por software.Permite microsegmentación, políticas automáticas y respuesta rápida. Base de la nube moderna.
Hiperconvergentes (HCI)Sistemas que integran en un mismo equipo cómputo, almacenamiento y red virtualizados, administrados desde una sola consola. Ej.: Nutanix, VMware vSAN.Menos componentes que proteger y gestión centralizada; si falla un nodo, otros asumen la carga.
PortabilidadCapacidad de mover datos y aplicaciones de un proveedor o entorno a otro sin rehacerlos.Evita la dependencia de un proveedor (lock-in); los contenedores y estándares abiertos la facilitan.
Cloud First (primero la nube)Estrategia en la que toda solución nueva se evalúa primero para implementarse en la nube antes que en infraestructura propia.Obliga a definir políticas de seguridad en la nube desde el diseño.
HDDC vs SDDC: en el HDDC "el hardware manda"; en el SDDC "el software manda" y el hardware es genérico. La nube pública es un gran SDDC.

IaaS — Infraestructura como servicio

El proveedor entrega servidores virtuales, almacenamiento y redes. El cliente instala y protege el sistema operativo, aplica parches, configura firewall y protege sus aplicaciones.

Ej.: AWS EC2, Azure Virtual Machines, Google Compute Engine.

Seguridad del cliente: parches del SO, antivirus, grupos de seguridad, cifrado de discos.

PaaS — Plataforma como servicio

El proveedor entrega una plataforma lista (SO, base de datos, servidor web) para que el cliente solo suba su código.

Ej.: Google App Engine, Azure App Service, Heroku, Firebase.

Seguridad del cliente: código seguro, gestión de claves y secretos, control de accesos.

SaaS — Software como servicio

El proveedor entrega la aplicación completa y la mantiene; el cliente solo la usa.

Ej.: Gmail, Microsoft 365, Zoom, Salesforce.

Seguridad del cliente: contraseñas fuertes, MFA, permisos de compartición, qué datos sube.

Analogía de la pizza: IaaS = te alquilan la cocina; PaaS = te dan la masa y el horno, tú pones los ingredientes; SaaS = te llevan la pizza lista a la casa.

3. Ciclo de vida en la seguridad de los datos

Los datos pasan por seis fases (modelo de la Cloud Security Alliance). En cada una se aplican controles distintos:

#FaseQué sucedeControles de seguridad
1CrearSe genera o captura el dato (formulario, archivo, sensor).Clasificar el dato (público, interno, confidencial), etiquetarlo, asignar dueño.
2AlmacenarSe guarda en una base de datos, disco o bucket.Cifrado en reposo, control de accesos, respaldos.
3UsarSe consulta, procesa o modifica.Autenticación, mínimo privilegio, registros (logs) de actividad.
4CompartirSe envía a otras personas o sistemas.Cifrado en tránsito (HTTPS/TLS), DLP (prevención de fuga de datos), enlaces con caducidad.
5ArchivarSe guarda a largo plazo aunque ya no se use diariamente.Almacenamiento seguro y económico, cifrado, políticas de retención legal.
6DestruirSe elimina cuando ya no es necesario.Borrado seguro, destrucción criptográfica (eliminar la llave de cifrado), certificado de eliminación.

4. Uso de cifrado de datos en la nube

Cifrar es transformar la información legible (texto plano) en información ilegible (texto cifrado) mediante un algoritmo y una llave. Solo quien tenga la llave correcta puede descifrarla.

Estados de los datos que se cifran

  • En reposo: datos guardados en discos, bases de datos o respaldos (ej. AES-256).
  • En tránsito: datos que viajan por la red (ej. HTTPS con TLS 1.2/1.3, VPN).
  • En uso: datos mientras se procesan en memoria (computación confidencial, enclaves seguros).

Tipos de cifrado

TipoCómo funcionaAlgoritmosUso en la nube
SimétricoUna sola llave para cifrar y descifrar. Muy rápido.AES-128, AES-256Cifrar discos, bases de datos y archivos.
AsimétricoPar de llaves: pública (cifra) y privada (descifra).RSA, ECCCertificados HTTPS, acceso SSH, firmas digitales.
Hash (no es cifrado reversible)Genera una "huella" única del dato; no se puede revertir.SHA-256, bcryptGuardar contraseñas, verificar integridad.

Gestión de llaves

  • KMS (Key Management Service): servicio del proveedor que crea, guarda y rota llaves (AWS KMS, Azure Key Vault, Google Cloud KMS).
  • HSM (Hardware Security Module): dispositivo físico a prueba de manipulación que protege las llaves.
  • BYOK (Bring Your Own Key): el cliente genera su propia llave y la carga al proveedor.
  • Cifrado del lado del cliente: los datos se cifran antes de subirlos; el proveedor nunca ve el contenido.
Regla de oro: "quien tiene la llave tiene los datos". Nunca se guardan llaves dentro del código ni junto a los datos que protegen.

5. Infraestructura de la seguridad en la nube

Asegurando la infraestructura

  • Seguridad física del data center (a cargo del proveedor): control biométrico, cámaras, guardas, energía redundante.
  • Endurecimiento (hardening) de VM: desactivar servicios innecesarios, cambiar contraseñas por defecto, aplicar parches.
  • Seguridad del hipervisor: aislamiento entre VM de distintos clientes.
  • Imágenes base seguras (plantillas aprobadas) para crear servidores.
  • Protección de endpoints: antimalware, EDR.
  • Respaldo y redundancia en varias zonas de disponibilidad.
  • Monitoreo y registros centralizados (SIEM).

Administración de la red

  • Red virtual privada (VPC / VNet): red aislada del cliente dentro de la nube.
  • Segmentación y subredes: subred pública (servidor web) y privada (base de datos).
  • Grupos de seguridad y firewalls: reglas que permiten solo el tráfico necesario (ej. solo puerto 443).
  • WAF (Web Application Firewall): protege aplicaciones web de ataques como inyección SQL.
  • Protección DDoS.
  • VPN o conexiones dedicadas para unir la oficina con la nube.
  • Microsegmentación: cada carga de trabajo solo se comunica con lo estrictamente necesario (enfoque Zero Trust).

Interfaces de gestión

Son los medios para administrar los recursos en la nube: consola web, línea de comandos (CLI), APIs y SDK. Son objetivos atractivos para atacantes porque dan control total.

  • Acceso solo por HTTPS y, si es posible, desde redes o IP autorizadas.
  • Registrar toda actividad de administración (AWS CloudTrail, Azure Activity Log).
  • Limitar las llamadas a API con tokens de corta duración y permisos mínimos.
  • Usar un bastion host o servicio de acceso seguro en lugar de exponer SSH/RDP a Internet.

Credenciales de administración

  • No usar la cuenta raíz (root) para el trabajo diario; protegerla con MFA y guardarla.
  • Autenticación multifactor (MFA) obligatoria para administradores.
  • Principio de mínimo privilegio: cada usuario solo con los permisos que necesita (IAM, roles).
  • Rotación periódica de contraseñas y llaves de acceso.
  • Gestores de secretos (AWS Secrets Manager, Azure Key Vault); nunca escribir credenciales en el código ni subirlas a GitHub.
  • Revocar accesos inmediatamente cuando alguien deja la organización.
  • Gestión de accesos privilegiados (PAM) y revisiones periódicas de permisos.

1. Aplicación de seguridad en la nube

Concepto de Cloud Broker

Un cloud broker (intermediario de servicios en la nube) es una persona, empresa o plataforma que actúa entre el cliente y uno o varios proveedores de nube. Ayuda a elegir, contratar, integrar, administrar y asegurar los servicios.

  • Intermediación: agrega valor a un servicio (ej. añade seguridad, reportes o administración de identidades).
  • Agregación: combina servicios de varios proveedores en uno solo.
  • Arbitraje: elige dinámicamente el proveedor más conveniente (precio, rendimiento).

Relacionado: CASB (Cloud Access Security Broker), herramienta de seguridad que se ubica entre los usuarios y las aplicaciones en la nube para aplicar políticas: visibilidad del uso, control de accesos, prevención de fuga de datos y detección de amenazas. Ej.: Microsoft Defender for Cloud Apps, Netskope.

Amenazas y riesgos

Amenaza: cualquier evento o actor que puede causar daño (un atacante, un malware, un error humano, un desastre).
Vulnerabilidad: debilidad que puede ser aprovechada.
Riesgo: probabilidad de que una amenaza aproveche una vulnerabilidad multiplicada por el impacto. Riesgo = Probabilidad × Impacto.

Principales amenazas en la nube

AmenazaDescripción
Configuraciones erróneasBuckets o bases de datos expuestos públicamente por error. Es la causa más frecuente de fugas.
Robo de cuentas y credencialesPhishing, contraseñas débiles o llaves publicadas en GitHub.
Interfaces y APIs insegurasAPIs sin autenticación o con errores permiten acceder a datos.
Amenazas internasEmpleados o ex empleados que abusan de sus accesos.
Malware y ransomwareCifran o roban la información almacenada en la nube.
Denegación de servicio (DDoS)Saturan el servicio para dejarlo fuera de línea.
Fugas de datos (data breach)Exposición de información confidencial.
Abuso del servicioUso de cuentas robadas para criptominería o enviar spam.

Riesgos

  • Pérdida de control y visibilidad sobre la infraestructura.
  • Dependencia del proveedor (lock-in) y quiebra o cierre del proveedor.
  • Incumplimiento legal por la ubicación de los datos en otros países.
  • Pérdida de datos sin respaldo.
  • Interrupción del servicio (caída del proveedor o de Internet).
  • Aislamiento deficiente entre clientes (multi-inquilino).
  • Daño reputacional y sanciones económicas.

Reducción de riesgos

Estrategias de tratamiento del riesgo: evitar, mitigar (reducir), transferir (seguros, contratos) o aceptar. Controles recomendados:

  • MFA y mínimo privilegio en todas las cuentas.
  • Cifrado en reposo y en tránsito.
  • Revisión automática de configuraciones (CSPM — Cloud Security Posture Management).
  • Respaldos regla 3-2-1: 3 copias, 2 medios distintos, 1 fuera del sitio.
  • Monitoreo continuo y alertas.
  • Capacitación de usuarios contra phishing.
  • Contratos y SLA claros con el proveedor.

Desarrollo de aplicaciones en forma segura

Consiste en integrar la seguridad en todas las etapas del ciclo de vida del software (SDLC seguro / DevSecOps, "seguridad desde el diseño").

  • Requisitos y diseño: modelado de amenazas, definir qué datos son sensibles.
  • Codificación: seguir guías como OWASP Top 10; validar entradas, evitar inyección SQL y XSS.
  • Pruebas: análisis estático (SAST), dinámico (DAST), escaneo de dependencias y de contenedores.
  • Despliegue: secretos en gestores seguros, infraestructura como código revisada.
  • Operación: monitoreo, parches y registros.

Modelos de identidad

ModeloDescripciónEjemplo
IAM (Identity and Access Management)Gestión de identidades y permisos: quién es el usuario y qué puede hacer.AWS IAM, Microsoft Entra ID.
Identidad centralizada / directorioTodas las cuentas en un único directorio.Active Directory.
Identidad federadaUna organización confía en la identidad emitida por otra, usando estándares como SAML, OAuth 2.0 u OpenID Connect."Iniciar sesión con Google" o con la cuenta del MEP.
SSO (Single Sign-On)Inicio de sesión único para acceder a varias aplicaciones.Una cuenta de Microsoft 365 para Teams, Outlook y OneDrive.
IDaaS (Identidad como servicio)La gestión de identidades se contrata en la nube.Okta, Auth0.
Control de acceso por roles (RBAC)Permisos según el rol (docente, estudiante, administrador).Roles en Google Classroom.
Zero Trust ("nunca confiar, siempre verificar")Cada acceso se verifica según identidad, dispositivo y contexto, aunque esté dentro de la red.Acceso condicional de Microsoft.

Marcos de referencia: ISO/IEC 27005, NIST SP 800-30, CSA Cloud Controls Matrix (CCM).

Gobernanza de datos

Es el conjunto de políticas, roles y procesos que definen cómo se gestionan los datos en la organización: quién es dueño de cada dato, cómo se clasifica, quién accede, cuánto tiempo se conserva y cómo se elimina.

  • Propietario de datos: decide sobre el uso del dato.
  • Custodio: lo administra técnicamente (a veces el proveedor).
  • Clasificación: público, interno, confidencial, restringido.
  • Calidad, trazabilidad y auditoría de los datos.

Implicaciones legales

  • Soberanía y ubicación de los datos: los datos quedan sujetos a las leyes del país donde se almacenan.
  • Costa Rica: Ley N.º 8968 de Protección de la Persona frente al Tratamiento de sus Datos Personales, supervisada por la PRODHAB. Ley 9048 (delitos informáticos, reforma al Código Penal).
  • Internacional: RGPD / GDPR (Unión Europea), CLOUD Act (Estados Unidos).
  • Contratos y SLA: definir responsabilidades, disponibilidad, notificación de incidentes y devolución de datos al terminar el contrato.
  • E-discovery: obligación de entregar información ante una investigación judicial.
  • Propiedad intelectual del software y de los datos.

Privacidad en servicios en la nube

  • Consentimiento informado del titular para recolectar sus datos.
  • Minimización: recolectar solo los datos necesarios.
  • Derechos ARCO: Acceso, Rectificación, Cancelación y Oposición.
  • Anonimización y seudonimización de datos personales.
  • Privacidad desde el diseño y por defecto.
  • Revisar las políticas de privacidad del proveedor y certificaciones como ISO/IEC 27018 (protección de datos personales en la nube).

4. Respuesta a incidentes

Un incidente de seguridad es un evento que compromete la confidencialidad, integridad o disponibilidad de la información (ej. acceso no autorizado, ransomware, fuga de datos). La respuesta a incidentes es el proceso organizado para detectarlos, contenerlos y recuperarse. Guía de referencia: NIST SP 800-61.

FaseAccionesEjemplo en la nube
1. PreparaciónPlan de respuesta, equipo (CSIRT), herramientas, contactos del proveedor, capacitación.Activar registros (CloudTrail), definir alertas, simulacros.
2. Detección y análisisIdentificar el incidente, confirmar, clasificar su gravedad.Alerta: una cuenta crea 50 servidores a las 3 a.m.

RA1 · Nube y virtualización

Resultado de aprendizaje: Analizar los componentes de la computación en la nube y el rol de la virtualización mediante modelos de implementación.

Ideas clave

  • La computación en la nube permite usar recursos informáticos por Internet, bajo demanda y pagando por lo que se consume.
  • La virtualización crea versiones simuladas de servidores, redes y almacenamiento; es la base que hace posible la nube.
  • El hipervisor tipo 1 se instala sobre el hardware (ESXi, Hyper-V, Xen); el tipo 2 sobre un sistema operativo (VirtualBox, Virtual PC).
  • Un contenedor comparte el kernel del anfitrión: es más liviano y arranca más rápido que una máquina virtual.
  • El NIST define cinco características esenciales: autoservicio, amplio acceso a la red, agrupación de recursos, elasticidad y servicio medido.
  • Los modelos de despliegue son pública, privada, híbrida, comunitaria y multicloud; cada uno equilibra costo, control y seguridad.

Host = equipo físico anfitrión; guest = sistema virtual invitado.

Un snapshot es una «foto» de la VM para volver atrás si algo falla.

Responsabilidad compartida: el proveedor protege la nube; el cliente protege lo que pone en la nube.

🛡️ Conexión con Ciberseguridad

Para un técnico en ciberseguridad, la virtualización es la herramienta del día a día: se usan máquinas virtuales para montar laboratorios, analizar malware sin riesgo y probar configuraciones. Elegir bien el modelo de nube también es una decisión de seguridad: define quién controla los datos y quién responde ante un ataque.

RA2 · Seguridad de datos e infraestructura

Resultado de aprendizaje: Distinguir la forma de organización de la nube y el aseguramiento desde la infraestructura hasta el software.

Ideas clave

  • En un SDDC el cómputo, la red, el almacenamiento y la seguridad están virtualizados y se controlan por software; en un HDDC dependen de hardware específico.
  • Según el modelo de servicio cambia quién protege cada capa: en IaaS el cliente protege el sistema operativo; en SaaS solo sus datos, usuarios y permisos.
  • Los datos pasan por seis fases: crear, almacenar, usar, compartir, archivar y destruir, y cada fase tiene sus propios controles.
  • Se cifra en reposo (AES-256), en tránsito (TLS) y en uso (computación confidencial).
  • El cifrado simétrico usa una llave; el asimétrico, un par de llaves; el hash crea una huella que no se puede revertir.
  • Las credenciales de administración se protegen con MFA, mínimo privilegio, rotación de llaves y gestores de secretos, nunca dentro del código.

«Quien tiene la llave tiene los datos»: nunca se guardan llaves junto a los datos ni en el código.

Analogía de la pizza: IaaS te alquilan la cocina; PaaS te dan masa y horno; SaaS te llevan la pizza lista.

La destrucción criptográfica elimina la llave para que los datos cifrados queden inservibles.

🛡️ Conexión con Ciberseguridad

La mayoría de las fugas de datos en la nube no ocurren por hackers geniales, sino por configuraciones erróneas y credenciales mal protegidas. Saber quién protege cada capa, cifrar bien y administrar las llaves es exactamente lo que hace un analista de ciberseguridad cuando revisa un entorno en la nube.

RA3 · Operaciones de seguridad

Resultado de aprendizaje: Evaluar la oferta de proveedores con respecto a la respuesta de incidencias por medio de las operaciones relacionadas con la seguridad en la nube.

Ideas clave

  • Un cloud broker es un intermediario entre el cliente y los proveedores; un CASB aplica políticas de seguridad entre usuarios y aplicaciones en la nube.
  • Riesgo = probabilidad × impacto; se trata evitándolo, mitigándolo, transfiriéndolo o aceptándolo.
  • La causa más frecuente de fugas en la nube son las configuraciones erróneas.
  • La identidad se gestiona con IAM, SSO, identidad federada, RBAC y el enfoque Zero Trust: nunca confiar, siempre verificar.
  • En Costa Rica la Ley 8968 protege los datos personales y la supervisa la PRODHAB.
  • La respuesta a incidentes tiene seis fases: preparación, detección y análisis, contención, erradicación, recuperación y lecciones aprendidas.

Para elegir proveedor se usa una matriz ponderada: certificaciones, SLA, ubicación, costo y soporte.

Respaldo 3-2-1: tres copias, dos medios distintos, una fuera del sitio.

SECaaS es contratar servicios de seguridad desde la nube: antivirus, WAF, SIEM o un SOC.

🛡️ Conexión con Ciberseguridad

Las operaciones de seguridad son el corazón del trabajo en un SOC: monitorear, detectar, responder y aprender de cada incidente. Evaluar proveedores con criterios de seguridad y saber qué exige la ley costarricense convierte al técnico en alguien que protege a la organización antes, durante y después de un ataque.
